01
把一个对象拆成了几张卡。一条任务的标题 / 属性 / 操作、明细、动态被拆成 3 张卡，中间夹灰缝，读起来像三件事；主按钮从底部挪到中间。客户（7 张）、审核右栏（4 张小卡）同理。
02
卡多了，边反而多了。每条灰缝是「描边 + 灰带 + 描边」。R29 报告里「贯穿线条变少」只算了细线，没算缝。
03
间距只有一档。卡内 16 = 卡间 16 = 区块 16，看不出哪几张是一组。
04
列表组头变成了内缩小药丸。R28 的贯穿色带是清楚的分组边界；R29 的小条像按钮。
05
画布偏暗、露得多。#F2F2F6 占屏 10–14%，整页发灰。
06
密度损失。订单页 4 个高指标格挤掉 4 行表格。
07
首屏动画过多。每次打开：骨架 360ms → 卡片错开上浮 → 数字滚动，约 1 秒后静止；运营待办的数据是本地的，这一秒只是推迟阅读。
08
R29 做对的。看板的指标格页签、图表卡、排行细条，以及抽屉、折叠、页签滑块、切换淡入这些回应操作的动效。R30 全部保留。

案例补充（文字结论，截图不发布）

本轮补看「什么时候不该用卡」：Linear 当前版应用、Plain、Attio（官网首屏实拍的产品界面）、Tailwind Catalyst 订单详情 / 列表、shadcn sidebar-inset / dashboard-01 / tasks、Tremor Dashboard 与 Insights、GitHub 议题；并合并 2026-10-19 灵感记录（间距三级、卡壳先行、图片内描边、表格数值细节）。

01
外壳 = 画布 + 嵌入式面板。Linear、Plain、Attio、Catalyst、shadcn sidebar-inset 都是侧栏在画布上、工作区一块嵌入面板，面板里没有卡片。
02
记录页是一块面 + 分区。Catalyst 订单详情用 14/600 小标题 + 分隔线分「Summary」「Payment method」，区块间距约 40。
03
卡片只给并列的同类。shadcn dashboard-01 只有 KPI 和图表是卡，表格直接放在面板上；GitHub 议题里每条评论是卡，右栏属性不是。
04
留白也能分组，前提是区块间距够大。Tremor 概览完全没有卡片，靠 48–64 的区块间距。
05
加载先出卡壳。卡片和标题先在位，只有内容区是骨架（design.how Quartz）。
