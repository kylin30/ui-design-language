同样的结构，少一半线。

R30「收敛」得 65 分，追平 R28 的最好成绩，没有批注。R31 不改方向：一个对象一块面、少拆卡、动效克制、控件全平。只把 Refactoring UI 审计出的十条落实下去：少边框、间距尺、灰字对比 ≥ 4.5、三级灰只给时间编号、字号六档、标签并进值里、彩色底不放灰字、色阶预先定义、五级投影、空状态给操作。每一条都对照 Linear、Stripe、Vercel Geist、Attio、GitHub Primer 的线上实测校准过。

为什么、改了什么

R30 的结构是对的：两块面、贯穿组头、操作条贴底。逐条对照 Refactoring UI 后，问题都在「细节的系统性」上：

01
线太多。面描边、分区线、表头线、工具栏线、分页线、操作条上线叠在一起，订单页首屏 70 条贯穿线。R31：面靠环 + 投影；分区靠间距；表头改浅色带；只留表格行线。
02
间距没有尺。最常用的是 6 和 10，另有 14 / 18 / 22 等零散值。R31：4 / 8 / 12 / 16 / 24 / 32 / 48；面内 24。
03
最浅的灰不及格，而且用得最多。#85858F 对白 3.65:1，占文字 26–48%。R31：#6A6B7B（5.25:1），只给时间、编号、计数；其余次要信息用 #565866（7.0:1）。
04
字号太碎。页面实际用到 10 / 11 / 12 / 13 / 14 / 15，12 和 13 只差 8%。R31：11 / 12 / 13 / 16 / 20 / 24。
05
标签压在每个值上。「状态 / 优先级 / 负责人」都能自明。R31：自明的去掉，其余并进值里读成一句。
06
彩色底上用中性灰、白字加透明度。R31：同色相手挑色 --p-meta、--on-dark。
07
色阶靠 color-mix 现调。R31：灰 11 级 + 主色 50–700，7 套主题各自定义。
08
只有两种投影。R31：五级两层投影；星蓝用环 + 顶部高光。
09
空状态只有两行灰字。R31：图标块 + 标题 + 一句话 + 一个操作；筛选为空给「清除筛选」。
10
星蓝主按钮白字只有 3.58:1（R30 就有，本轮量化时发现）。R31：实心按钮底 #5B68E0（4.67:1），链接仍用 #6E7CF5。

F10 · 空状态 = 图标 + 一句话 + 一个操作

正确 · 空状态 = 图标 + 一句话 + 一个操作
没有符合条件的售后单当前的搜索词或筛选条件下没有记录。
筛选为空：保留筛选条，给「清除筛选」。全部办完：列表和详情都说明，给「查看今天已办」。切到没有数据的栏：给「回到需要我」。

没有符合条件的售后单

依据：Refactoring UI「Don't overlook empty states」；Geist 空状态（40px 图标块 + 标题 + 一句话 + 操作）、GitHub「No results matched your search」保留筛选条。

保留的结构规则（R30）

  • 一个对象 = 一块面 .sheet；标题、属性、明细、动态是面里的分区。
  • 同类并列才用卡：看板指标格、图表卡、排行卡、订单紧凑指标格。
  • 列表组头是贯穿色带（36px，状态图标 + 组名 + 计数，可折叠）。
  • 操作条贴在对象底部（后果说明 + 按钮，sticky；R31 改为浅色带）。
