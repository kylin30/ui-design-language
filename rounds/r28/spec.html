先临摹，再设计。

R27「素净」得 55 分，批注「多参考下案例再做，不要急着交差」。这是第二次被说「急」（R21 也是）。R28 先收集 43 张已上线产品的真实截图、把其中 6 张逐像素复刻成 HTML 并和截图做差（每个演示类型至少一张），量出它们的字号、灰阶、行高、线色和间距，再用这些数字重写唯一一份 app.css，六个演示各对应案例库里的一个具体产品模式，最后逐页和参考并排复核：初版 4 轮，深化阶段每页再 3–5 轮，收尾做了模糊测试、噪音计数和深色检查。

案例库结论

案例库共 43 张（私有，不随站点发布）：Linear 6、Stripe 2、Vercel 3、Attio 3、Plain 2、Intercom、Front、Groove、Kitemaker、Cardinal、Spendesk、Flow、Laserfocus、Sentry 4、PostHog 2、Compound、June、GitHub 3、Notion、飞书 4，以及 Ant Design Pro、Jira 作为反例。阿里云控制台、Datadog、Shopify 后台的帮助页取不到真实界面截图，Mobbin 需要登录，X 上搜到的多为概念稿，均未采用。每张都记录了来源、模式、为什么干净、实测令牌（底色、线色、文字灰阶、字形高、行距）。

01
工作区是一整块白。Linear #FCFCFC、Attio / Stripe / Notion #FEFEFE–#FFF；侧栏只深 1–2%（#FAFAFA / #FBFBFB），中间一条发丝线。灰画布 + 白卡片只出现在看板（Compound #F4F6F8、PostHog）。测量：底色占比（measure_case.py），43 张中 31 张主区为白或近白。
02
线极浅，且只有一种。Stripe #E3E8EE、Attio #E7E7E7、Notion #E9E9E7、Vercel #EDEDED、Linear 0.5px 发丝线。表格基本只有横线。测量：横线颜色直方图。
03
字小而统一。行和正文 13px（Linear）或 14px（Attio、Stripe），标签 12px；页面标题放在 48px 顶栏里，只有 14–15px/600。28px 大标题只出现在 Stripe 的列表落地页。测量：字形高度 + 逐字宽度标定（复刻时按文字框宽度反推字号）。
04
行 36–40px，单行。Stripe 36、Attio 36、Linear 40、GitHub 约 32。第二信息进右侧固定列（时间、负责人、金额），不塞第二行。测量：横线间距 / 文字行间距。
05
分组要一眼可见。长列表：Linear「我的事项」用一条贯穿的极浅色带做组头（状态图标 + 名称 + 计数），组头本身就是分隔。记录页内部：Linear 客户页、Kitemaker 用小标签 + 计数 + 拉满的线，组间距约为组内距的 1.6 倍。两种都不用圆角灰块。
06
记录页是「标签 / 值」。Linear 属性行（列间 40px）、Intercom Details、GitHub 右栏、Laserfocus 分节：12px 灰标签 + 13px 值，节与节之间一条线或 24px 留白。
07
状态只给图标上色。Linear 14px 状态圆，Attio 7px 色点，Sentry 的级别是 3px 色条；文字保持黑或灰，只有真正的错误才让文字变红（Stripe「Delete draft」、Sentry「Unhandled」）。
08
反例的共同点。Ant Design Pro 分析页、Jira、Front、Groove：第一屏堆满指标卡、图表、按钮，颜色多、层级靠颜色。r20–r27 的页面骨架（大标题 + 一句话 + 4 张指标卡 + 两张浮动卡）正是 Ant Pro 分析页的骨架。

六张逐像素复刻

分两批：先 3 张，深化阶段再给剩下三类演示（告警、审核、看板）各补 1 张。每张都挑最接近我们演示类型的参考，测量后写成 HTML，用无头浏览器按参考图的像素密度渲染，和原图叠出热力图，反复改到文字框位置误差 ≤1–2px。第一次复刻 Linear 时把原图当成 2 倍图，所有字都大了 13%——之后统一先用一个已知字号（属性值 13px）反推缩放比，再测其他尺寸。

r20–r27 缺了什么

  1. 页面骨架错了：每页都是「28px 大标题 + 说明句 + 4 张指标卡 + 两张浮动卡」。参考里只有看板这样做；队列、订单、客户、审核都是「48px 顶栏 + 工具栏 + 铺满的列表 / 表格 + 详情」。
  2. 灰缝 + 卡片：区域之间用 24px 灰缝和圆角卡片分开，每屏 3–6 个框；参考用一块白面板 + 1px 线。
  3. 两行条目：队列每项三行（标题、副标题、日期），高约 50；参考单行 36–40。
  4. 字偏大、档位多：正文 14/22、标题 28、指标 24；参考正文 13–14、标签 12、顶栏标题 14–15。
  5. 状态染色：「超时 11 天」「疑似辱骂」整段彩色；参考只给图标上色。
  6. 分组不明显：组头是灰色小字、无线、组间距≈行距；参考是标签 + 计数 + 线，组间距 1.6 倍。
  7. 侧栏和主区没有边界：同为灰底；参考侧栏深 1–2% + 一条发丝线（或外框 + 白面板）。
  8. 属性被拉散：详情属性三等分；参考固定列间 40px。

收尾 · 新眼睛检查

模糊测试：六页首屏高斯模糊后，每页只剩一个焦点（选中项、GMV 曲线、P99 曲线、风险条、表格、席位柱），没有跳出来的色块；据此去掉了告警迷你柱下的深色基线（模糊后是 9 条横杠）和「筛选」虚线框，改短一条被截断的副标题，审核标签 11.5px 归到 12px。

噪音计数（r27 → r28，首屏）：字号 4–7 档、字重 3 档、文字样式 8–13 种、截断 0，与 r27 持平或更少；线色比 r27 更浅（#ECECEF）。如实记录：订单 / 告警 / 审核三页的可见线条从 43 / 28 / 33 增到 57 / 36 / 43，运营待办的带色面积从 3.5% 到 7.5%——前者是首屏行数翻倍（订单 9 → 20 行）和新增的已恢复组、内容卡，后者是 5 条分组色带。这是对「信息太少、太空」的有意交换：信息变多，样式种类不增加。

深色「星蓝」：六页逐一检查，灰勾、色带（白 3%）、上周虚线、抽屉投影、内容卡边框都有层次，没有浅色专用的硬编码颜色。

验收清单

  • 一块白面板，不出现浮动卡片；区域之间只有 1px 线。
  • 列表行 40、表格行 36，单行；副信息在右侧固定列。
  • 分组 = 标签 + 计数 + 线，组间距大于组内距。
  • 状态颜色只在 14px 图标上；红色只给越线的数字和危险操作。
  • 记录属性用属性行；看板指标用统计条。
  • 字号只用 12 / 13 / 14 / 20 / 24，字重 400 / 500 / 600；无衬线。
  • 控件平：无渐变、无投影；投影只给浮层。
  • 长列表分组用色带；完成态是灰勾 + 次要色。
  • 图表从 0 起、3 个刻度、真实粒度；严重度不靠给图表染色。
  • 队列的每个流转操作都有快捷键；点哪条，详情就是哪条。
  • 深色主题结构一致；1280 宽无横向滚动。
