# 后台视觉规范 v4.0（Round 2）

> **一句话**：这是一套**与 UI 库无关**的视觉规范。不管你用 Ant Design、Element Plus、shadcn/ui、MUI 还是手写 CSS，照着它做出来的后台都长得像同一个产品。
>
> 气质：**冷静、专业、整齐**。适用：后台管理系统、运营后台、SaaS 控制台。
>
> v2.0（2026-10-10）：从“一套皮肤”改写为“一套规范”。规范只规定**角色、比例和规则**；具体色值和像素放进「参考实现」，可以替换。

---

## 0. 怎么读这份文档

规范分三层，越往上越稳定：

| 层 | 内容 | 能不能改 | 在本文哪里 |
|---|---|---|---|
| **① 规则层** | 原则、层级、组合方式、什么能出现在哪里 | 不改。这是“像不像这个产品”的根本 | §2、§6、§7 |
| **② 角色层** | 颜色角色、字号阶梯、间距单位、圆角/阴影级别，以及它们之间的**比例和约束** | 很少改。改了等于换了一版规范 | §3–§5 |
| **③ 取值层** | 某个角色具体是 `#18181B` 还是别的颜色，是 32px 还是 36px | 可以换。只要满足角色层的约束 | §3.4 参考实现、`reference-tokens.css` |

**落到某个 UI 库时**：先按 §3.3 / §8 把库自带的 token 对到角色上，再用 §7 的行为规则约束组件怎么用。不需要换库，也不需要重写组件。

本文不打开 demo 也能读完、能执行。`demo.html` 只是一份“照规范做出来长什么样”的样例。

## 0.5 Identity：换任何库都认得出来的五个签名（v4.0）

> 这一节属于**规则层**。色值可换，但下面五条签名必须保留；它们决定“这是我们的后台”，而不是“又一个 shadcn / Ant 默认皮肤”。

1. **有温度的中性（暖石灰）**：中性色不用纯灰、不用冷蓝灰、**不用绿灰**，统一带极轻的暖色相（OKLCH 色相约 70–95°，彩度 ≤ 0.012）。页面底、侧栏、发丝线、正文全部同一温度。
2. **靛墨操作 + 朱印关注**：主操作用深靛墨（不是黑、不是亮蓝、不是绿；HSL 饱和度 ≤ 50%，白字对比 ≥ 4.5:1）；关注色是朱砂红，**像盖章一样**：一屏最多一处，以 3px 竖条（“印条”）或细框角标出现，从不铺大面积底色。朱砂与 danger 明度/色相必须拉开（danger 更暗更正红，朱砂偏橙）。
3. **刻线标签（Ruled labels）**：侧栏分组、KPI 标题、表头使用等宽字体、11px、全大写/加字距的“仪表标签”；分组标题后接一条延伸发丝线。中文标签照常写，只是字体与字距统一。
4. **方点状态语言**：状态不用彩色胶囊底，只用 7×7px **方点 + 正文色文字**。颜色只留在点上，整列状态读起来是“一排刻度”，不是彩虹。
5. **数字用等宽、页面标题用衬线**：金额、数量、编号、KPI 一律等宽 + tabular；只有页面 h1 用中文衬线（宋体系），其余全部无衬线。焦点用 2px 实线 outline + 2px 间距（靛墨色），不用模糊光晕。

**页面层补充（v4.0）**：标题下一行“一句数字摘要”（视图概况）；画布 / 面板 / 内嵌行三层底色分层，优先底色差而非阴影；记录用三段式（主标题 / 编号·描述 / 元数据）；侧栏计数徽标默认中性，异常才用朱印色。

**为什么不是 shadcn**：shadcn 默认 = 纯锌灰 + 黑按钮 + 圆角 6–8 + 彩色胶囊 Badge + 光晕焦点 + 全无衬线。本规范在中性温度、操作色、状态形态、字体分工、焦点形态五处全部不同，且圆角收紧到 2/4/6/8。

**落到任何库时怎么保留签名**：颜色走 §3.3 角色映射；“方点状态”在 Ant 用 `Badge status` + 自定义方形、在 Element 用 `el-tag` 去底改 `::before`；“刻线标签”是一条全局 class（等宽 + 11px + 字距）；“朱印”是一个只允许出现一次的 `attention-mark` 组件。签名都是 1–2 条 CSS 覆盖，不需要重写组件。

## 1. 目的与范围

### 1.1 解决什么问题

同一个团队、同一个人，换一个项目换一个组件库，做出来的后台就换了一副面孔：Ant 的蓝、Element 的蓝、shadcn 的黑，圆角、行高、按钮层级都不一样。问题不在库，而在**没有一份高于库的决定**。

这份规范就是那份决定。它回答的是：

- 页面上哪些东西该有颜色，哪些不该；
- 字号分几级，数字怎么排；
- 东西之间隔多远，多密算合适；
- 一个后台页面由哪些块组成，按什么顺序摆；
- 主按钮、次按钮、状态标签、空状态这些东西**什么时候用、用几个**。

### 1.2 管什么，不管什么

| 管 | 不管 |
|---|---|
| 颜色**角色**与使用比例 | 组件的 API、props、实现代码 |
| 字号阶梯、字重、数字排版 | 选哪个组件库 |
| 间距单位、密度、圆角与层级的比例 | 动画库、图标库的选型（只约束用法） |
| 后台页面的版式组合 | 业务逻辑、交互流程 |
| 组件的**层级与行为规则** | 品牌 VI、营销页、移动端 App |

## 2. 原则：可以直接拿来做判断的规则

原则不是形容词，是遇到分歧时用来裁决的规则。每条都附一个判断题。

1. **信息先于装饰。**
   界面上每一个元素都要回答“它帮用户做了什么判断”。答不出来就删。
   不用插画、渐变、装饰线、彩色图标底；卡片默认不加阴影。
   *判断：去掉它，用户会少知道什么吗？不会 → 删。*

2. **颜色是职责，不是装饰。**
   中性色占界面面积的 **90% 以上**。有颜色的地方只能是三种之一：**可操作**（主操作色）、**需关注**（关注色）、**状态**（语义色）。
   *判断：这块颜色属于这三种的哪一种？都不是 → 改成中性色。*

3. **整齐来自网格，不来自边框。**
   所有尺寸取自同一个基础单位（§5）。左边缘对齐，数字右对齐，同一行控件同高。对齐做好了，就不需要靠加线、加底色来“分组”。
   *判断：这条分隔线去掉后，分组还清楚吗？清楚 → 去掉。*

4. **一处一个重点。**
   每个视图区域（页面头、抽屉、弹窗、卡片）**最多一个**主操作；关注色一屏**最多 2 处**。稀缺，所以有分量。
   *判断：用户第一眼会看哪里？如果答案有两个，降级其中一个。*

5. **密而不挤。**
   后台允许高密度，但密度靠**统一压缩比例**实现（§5.3 密度档），不靠随手减某一处的间距。宁可少一列，也不要把单元格内边距压到 8px 以下。
   *判断：这个间距是密度档里的值，还是临时拍的？临时拍的 → 改回档位值。*

6. **安静优先。**
   动效只用来说明“东西从哪来、到哪去”（抽屉滑入、下拉展开），时长 120–200ms。不用弹跳、不用循环动画、不用动效吸引注意力。
   *判断：关掉这个动画，用户会迷路吗？不会 → 可以不要。*

## 3. 颜色：角色，而不是色板

### 3.1 先定角色，再谈色值

规范只定义**颜色角色**。任何一个 UI 库、任何一套色值，只要把这些角色对上并满足 §3.2 的约束，就是合规的。

| 角色 | 含义 | 典型位置 | 面积占比 |
|---|---|---|---|
| **canvas** 画布 | 最底层背景 | 页面底、侧栏底 | 大 |
| **surface** 表面 | 承载内容的容器 | 卡片、表格、抽屉、弹窗、输入框底 | 大 |
| **surface-subtle** 弱表面 | 容器内的次级分区 | 表头、筛选区、代码块 | 小 |
| **surface-hover / selected** | 交互反馈底色 | 行悬停、行选中、菜单当前项 | 小 |
| **border** 边框 | 容器边界、分隔线 | 卡片边、表格行线 | 线 |
| **border-strong** 强边框 | 可交互控件的边界 | 输入框、次按钮、复选框 | 线 |
| **text-1** 主文字 | 标题、正文、数据 | — | — |
| **text-2** 次文字 | 辅助正文、菜单未选中项 | — | — |
| **text-3** 弱文字 | 说明、表头、占位、时间戳 | — | — |
| **text-disabled** 禁用文字 | 不可用状态 | — | — |
| **action** 主操作色 | “可以点、点了会推进事情” | 主按钮、当前页码、选中复选框、Tab 下划线、链接 | ≤ 3% |
| **attention** 关注色 | “这里需要你看一眼” | 需关注 KPI、待办计数、提示条 | ≤ 1% |
| **success / warning / danger / info** 语义色 | 只表达**结果或状态** | 状态标签、校验信息、通知、涨跌 | ≤ 3% |

每个有颜色的角色（action、attention、语义色）都需要三个档：**实色**（文字/图标/实心块）、**浅底**（soft，标签和提示条的底）、**边框**（可选）。

### 3.2 角色之间的约束（换色值时必须满足）

这是规范真正“锁死”的部分。色值可以换，下面这些关系不能破：

1. **中性色同一色温。** canvas、surface、border、text 全部取自同一条灰阶（全冷灰或全暖灰），不混用。
2. **canvas 与 surface 有可见但很轻的差异**：亮度差约 2%–4%（例如 `#FAFAFA` vs `#FFFFFF`）。差太大界面会“碎”，没差异卡片就要靠阴影撑，违反原则 1。
3. **文字三档的对比度**（对 surface）：text-1 ≥ 12:1，text-2 ≥ 7:1，text-3 ≥ 4.5:1。text-3 是可读文字的底线，比它更浅的只能用于禁用和装饰。
4. **action 低饱和或无彩。** 主操作色可以是近黑、深灰蓝、深青等**稳重色**；饱和度 HSL ≤ 50%；白字在其上对比度 ≥ 4.5:1。不用亮蓝、亮紫、亮橙做主操作色。
5. **attention 必须和所有语义色拉开**：色相距离 danger / warning / success / info 都 ≥ 30°，且饱和度低于 danger。关注色的意思是“请看一眼”，不能被误读成“出错了”或“成功了”。
6. **attention ≠ action。** 两者色相不同。如果主操作色本身已经是有彩色（例如深蓝），关注色要选和它拉开 ≥ 60° 的色相，或干脆不用关注色，只用 warning-soft 承担。
7. **语义色降饱和**：四个语义色的饱和度大致一致，明度接近，放在一起不应有一个特别跳。浅底（soft）统一取实色的 6%–10% 透明度或等效浅色。
8. **一个产品只有一个“非语义彩色”。** 除了语义色，界面上最多出现一个色相（attention 或有彩的 action，二选一）。这条是“冷静”的保证。

### 3.3 怎么对到任何 UI 库

几乎所有成熟的 UI 库都有一套自己的 token，名字不同、角色相同。落地时**只改库的 token 值，不改组件**。下表是主流库的对应关系：

| 规范角色 | Ant Design 5（`theme.token`） | Element Plus（CSS 变量） | shadcn/ui（CSS 变量） | MUI（`createTheme`） |
|---|---|---|---|---|
| canvas | `colorBgLayout` | `--el-bg-color-page` | `--background`（页面级） | `palette.background.default` |
| surface | `colorBgContainer`、`colorBgElevated` | `--el-bg-color`、`--el-bg-color-overlay` | `--card`、`--popover` | `palette.background.paper` |
| surface-subtle | `colorFillQuaternary` / Table `headerBg` | `--el-fill-color-light` | `--muted` | 自定义 `palette.surfaceSubtle` |
| surface-hover | `controlItemBgHover` | `--el-fill-color-light` | `--accent`（⚠ 见下） | `palette.action.hover` |
| border | `colorBorderSecondary`、`colorSplit` | `--el-border-color-lighter` | `--border` | `palette.divider` |
| border-strong | `colorBorder` | `--el-border-color` | `--input` | 组件级 `outlined` 边框色 |
| text-1 | `colorText` | `--el-text-color-primary` | `--foreground` | `palette.text.primary` |
| text-2 | `colorTextSecondary` | `--el-text-color-regular` | `--muted-foreground`（偏深一档时） | `palette.text.secondary` |
| text-3 | `colorTextTertiary` | `--el-text-color-secondary` | `--muted-foreground` | 自定义 `palette.text.tertiary` |
| text-disabled | `colorTextQuaternary` | `--el-text-color-placeholder` | 透明度 50% 的 foreground | `palette.text.disabled` |
| action | `colorPrimary`（同时设 `colorLink`） | `--el-color-primary` 及 `-light-*` / `-dark-2` | `--primary` / `--primary-foreground`，`--ring` | `palette.primary.main` |
| attention | **无原生 token** → 扩展 | **无** → 扩展 `--app-attention` | **无** → 扩展 `--attention` | 扩展 `palette.attention` |
| success | `colorSuccess` | `--el-color-success` | 扩展 `--success` | `palette.success.main` |
| warning | `colorWarning` | `--el-color-warning` | 扩展 `--warning` | `palette.warning.main` |
| danger | `colorError` | `--el-color-danger`、`--el-color-error` | `--destructive` | `palette.error.main` |
| info | `colorInfo`（⚠ 默认跟随 primary） | `--el-color-info`（⚠ 默认是灰） | 扩展 `--info` | `palette.info.main` |

**三个最容易踩的坑：**

- **shadcn 的 `--accent` 不是本规范的 attention。** shadcn 的 accent 是悬停底色，对应 surface-hover。本规范的关注色要另起一个 `--attention`。
- **Ant Design 的 `colorInfo` 默认等于 `colorPrimary`。** 主操作色改成近黑后，info 会跟着变黑。必须单独设定 `colorInfo`。
- **Element Plus 的 `info` 默认是中性灰。** 它的 info 标签其实承担的是“中性状态”。按本规范：中性状态用 Element 的 `info`，真正的“信息”语义另设或用 `primary` 的浅色 Tag 代替，**团队内统一一种即可**。

**关注色（attention）在任何库里都是扩展**：定义一个变量，只在 §7.2 列出的几个位置手动使用，不去覆盖库的任何组件默认色。

## 4. 字体排印

### 4.1 字族

- **界面字体**：系统无衬线优先，中文跟随系统。参考栈：`Inter, "PingFang SC", "HarmonyOS Sans SC", "Noto Sans CJK SC", "Microsoft YaHei", system-ui, sans-serif`。
- **等宽字体**：只用于编号、代码、哈希、对齐要求极高的 ID。参考栈：`"JetBrains Mono", "SF Mono", Menlo, Consolas, monospace`。
- 一个产品只用**一套**无衬线 + **一套**等宽。不引入第三种字体，不用衬线体。
- 库自带字体不一致时，以本规范为准覆盖库的 `fontFamily` / `--el-font-family` / `font-sans`。

### 4.2 字号阶梯

以**正文 = 14px** 为基准，阶梯如下。用相对名称记，落地时按档位取值：

| 档位 | 参考值 | 行高 | 用途 |
|---|---|---|---|
| caption | 12px | 18–20px | 表头、标签、辅助说明、时间戳 |
| body-sm | 13px | 20px | 表格正文、紧凑控件 |
| **body** | **14px** | **22px** | 默认正文、表单、按钮 |
| title-sm | 16px | 24px | 卡片标题、抽屉/弹窗标题 |
| title | 20px | 28px | 页面标题（一页一个） |
| display | 24px | 32px | KPI 数字 |
| display-lg | 30px | 38px | 大屏数字（少用） |

**规则：**

- **一屏最多出现 4 个字号档**。超过就说明层级没想清楚。
- 行高一律落在 **4 的倍数**上，保证与间距网格对齐。
- 库的默认正文不是 14px 时（MUI 默认 14/16 混用、部分库默认 12px），统一改到 body 档。
- 中文不加字间距（`letter-spacing: 0`）；只有 caption 级全大写英文缩写可加 0.02–0.04em。

### 4.3 字重

只用三档：**400 常规**、**500 中等**、**600 半粗**。

- 400：正文、表格数据、说明。
- 500：按钮文字、当前导航项、表头（可选）、标签。
- 600：页面标题、卡片标题、KPI 数字。
- **禁用 700 及以上**。后台的层级靠字号和颜色档拉开，不靠粗体。

### 4.4 数字

后台一半以上的信息是数字，单独立规：

1. **所有数字开启等宽数字**：`font-variant-numeric: tabular-nums`（或 `font-feature-settings: "tnum"`）。在根节点开，任何库都生效。
2. **金额、数量、百分比在表格里右对齐**；表头跟随列的对齐方向。
3. 千分位分隔；金额固定小数位（通常 2 位），同一列小数位一致。
4. 单位和货币符号比数字**小一档、浅一档**（例：`¥` 用 body 档 + text-2，数字用 display 档 + text-1）。
5. 涨跌用语义色，**颜色表示好坏，不表示方向**：退款率上升是坏事，用 danger，即使箭头朝上。
6. 编号、ID 用等宽字体 + body-sm 档；不要用等宽字体排金额。

## 5. 间距、密度、圆角、层级

### 5.1 基础单位

**基础单位 u = 4px。** 所有间距、尺寸、行高取 u 的整数倍；常用值是 2u 的倍数。

间距阶梯（以 u 计）：`1u 2u 3u 4u 5u 6u 8u 10u 12u` → 参考值 `4 8 12 16 20 24 32 40 48`。不在阶梯里的值不要出现（1px 发丝线除外）。

### 5.2 间距规则

1. **内小外大**：元素内部的间距 ≤ 元素与相邻元素的间距。按钮里的图标和文字隔 1.5u，按钮之间隔 2u，按钮组和标题隔 4u。
2. **同级同距**：同一组里的同级元素间距相同。KPI 卡之间、区块之间统一 4u。
3. **页面边距 = 6u**（参考 24px），紧凑档 4u。
4. **容器内边距 = 4u–6u**：卡片 4u–5u，抽屉/弹窗 6u。
5. **表格单元格左右 3u**；首列、末列与容器边缘对齐容器内边距（5u）。
6. **表单**：label 与控件 1.5u；表单项之间 4u；分组之间 6u。

### 5.3 密度档

密度不是某个组件的属性，是**整页的统一缩放**。三档的比例关系固定：

| 量 | 紧凑 | **默认** | 舒适 | 比例规则 |
|---|---|---|---|---|
| 控件高度 C | 7u（28） | **8u（32）** | 10u（40） | 基准量 |
| 表格行高 | 9u（36） | **11u（44）** | 13u（52） | ≈ C + 3u |
| 表头行高 | 9u | **10u（40）** | 11u | 行高 − 1u |
| 按钮左右内边距 | 3u | **4u** | 5u | ≈ C / 2 |
| 页面边距 | 4u | **6u** | 6u | — |

- 一个页面只用一档。切换密度时以上数值**一起变**。
- 同一行的输入框、选择器、按钮、日期选择器**同高 = C**。各 UI 库都有全局尺寸开关（Ant `controlHeight`、Element `--el-component-size`、MUI `size` 默认值、shadcn 按钮 `h-*`），统一设到 C。

### 5.4 圆角

圆角分三级，**由控件高度推出**，不独立拍：

| 级别 | 规则 | 参考值（C = 32） | 用于 |
|---|---|---|---|
| r-control | ≈ C × 0.19，取 4–8 | 6px | 按钮、输入框、标签、菜单项 |
| r-container | r-control + 2 | 8px | 卡片、下拉面板、提示条 |
| r-overlay | r-container + 2 | 10px | 弹窗 |
| r-mini | 4px | 4px | 复选框、角标 |
| pill | 全圆 | — | 只用于计数徽标、头像 |

- **嵌套规则**：内层圆角 = 外层圆角 − 两者之间的内边距（最小 2px）；内边距大于外层圆角时，内层用自己的级别即可。
- **全产品最多 3 个常用圆角值。** 库默认圆角不同（Ant 6、Element 4、shadcn 0.5rem、MUI 4）时，一律改到本规范的值。
- 不做一边圆一边方，不做超大圆角（≥ 16px）的卡片。

### 5.5 层级（elevation）

**默认平铺，用边框分层，不用阴影。** 阴影只给“浮在内容之上”的东西。

| 层级 | 何时使用 | 表现 |
|---|---|---|
| L0 平铺 | 卡片、表格、筛选区 —— 绝大多数容器 | 无阴影，1px border |
| L1 贴附 | 吸顶表头、吸顶工具栏 | 极轻阴影（不透明度 ≤ 4%） |
| L2 浮层 | 下拉、气泡、日期面板 | 轻阴影（≈ 6%），可去掉边框 |
| L3 模态 | 抽屉、弹窗 | 较深阴影（≈ 12%）+ 遮罩（≈ 28% 黑） |

- 阴影颜色取中性色最深一档的透明度，不用纯黑、不用彩色阴影。
- **同一层级只用一种阴影**；不允许“卡片悬停时浮起来”这类装饰性阴影变化。
- z 轴顺序固定：吸顶 < 下拉 < 抽屉 < 弹窗 < 全局提示。

## 6. 后台版式：组合规则

### 6.1 页面骨架

```
┌──────────┬─────────────────────────────────────────────┐
│          │ 顶栏：面包屑 ·············· 搜索 · 通知 · 用户 │
│  侧栏    ├─────────────────────────────────────────────┤
│          │ 页面头：标题 + 说明 ··········· 次操作 主操作 │
│  分组    │ KPI 行（可选，2–4 个）                        │
│  导航    │ 主内容卡：Tabs → 筛选栏 → 批量条 → 表格 → 分页 │
│          │                                             │
└──────────┴─────────────────────────────────────────────┘
                                         抽屉（从右侧覆盖）
```

**纵向顺序固定**：页面头 → KPI 行 → 主内容。块与块之间统一 4u。不在页面头上方再放横幅（系统级公告除外，且可关闭）。

### 6.2 侧栏

- 宽度 56u（参考 224px），折叠 16u（64px）。
- **与画布同色**（canvas），用 1px border 和内容区分开。不用深色侧栏、不用品牌色侧栏。
- 菜单项高 9u，图标 16px，图标与文字隔 3u。分组标题用 caption + text-disabled。
- 当前项：surface-selected 底 + text-1 + 500 字重。**不用主操作色实心块**做当前项。
- 计数徽标默认中性；只有“需要处理”的计数可以用关注色（算入一屏 2 处的配额）。
- 层级最多两级；三级菜单说明信息架构要重排，而不是继续缩进。

### 6.3 顶栏

- 高度 14u（56px）= 控件高 C + 上下各 3u。surface 底 + 底部 1px border。
- 左：面包屑（body-sm，末级 text-1 + 500，前级 text-3）。右：全局搜索 → 图标按钮 → 用户。
- 顶栏不放主操作按钮。顶栏不放页面标题（标题属于页面头）。

### 6.4 页面头

- 左：页面标题（title 档，600）+ 一行说明（body-sm，text-3，写数据口径或更新时间）。
- 右：操作区，**底对齐**标题区。顺序从左到右：文字按钮 → 次按钮 → 主按钮（主按钮永远在最右）。
- 一个页面头最多 1 个主按钮 + 2 个次按钮；更多操作收进“更多”下拉。

### 6.5 KPI 行

- 2–4 张等宽卡片，一行排完；超过 4 个放进报表页，不在列表页堆指标。
- 卡片内部顺序：指标名（body-sm，text-3）→ 数值（display，600）→ 对比/趋势（caption）。
- 迷你趋势图只用中性色，最后一个点可用主操作色；不画彩色面积图。
- 需要人处理的指标可以标“需关注”（关注色边框 + 小标签），**整行最多 1 张**。

### 6.6 筛选栏

- 放在主内容卡内、表格上方，surface-subtle 底，与表格共享一个容器。
- 字段从左到右按使用频率排；常驻 3–5 个，其余折叠到“更多筛选”。
- 每个字段：label 在左（或上），控件同高 C，同一行宽度按网格均分。
- 末尾“重置（文字按钮）+ 查询（次按钮）”。**查询不是主按钮**：主按钮名额留给页面级动作。

### 6.7 表格

- 列顺序：选择框 → 主键（编号/名称）→ 描述字段 → 数值 → 状态 → 时间 → 操作。
- 文本左对齐，数值右对齐，状态和操作左对齐。不居中（除了纯图标列）。
- 表头：caption 档，text-3，surface-subtle 底；行线用 border 的最浅一档；**不用斑马纹、不用竖线**。
- 行悬停 surface-hover；选中 surface-selected。选中多行时，在表格上方出现批量条（action-soft 底）。
- 行内操作用文字链接，最多 3 个，危险操作放最后并用 danger 文字色；更多收进“…”。
- 分页在表格下方，左侧写“共 N 条”，右侧页码。当前页用主操作色。

### 6.8 抽屉与弹窗

- **抽屉**用于查看详情、编辑单条记录（保持列表上下文）；**弹窗**只用于确认和短表单（≤ 5 个字段）。
- 抽屉从右侧出，宽度两档：120u（480px）/ 180u（720px）。头部高度 = 顶栏高度，与顶栏对齐。
- 结构：头（标题 + 关闭）→ 体（分节，节间 6u）→ 底（操作，右对齐，主按钮在最右）。
- 抽屉/弹窗底部同样遵守“一个主按钮”。

## 7. 组件层级与行为规则

这些规则不依赖任何组件实现。用 Ant 的 `Button type="primary"`、Element 的 `el-button type="primary"` 还是 shadcn 的 `<Button>`，都按同一张表决定用哪个。

### 7.1 按钮层级

| 层级 | 外观（角色） | 什么时候用 | 数量 |
|---|---|---|---|
| **主按钮** primary | action 实心底 + 反白字 | 推进当前任务的那一个动作：新建、提交、保存 | 每个视图区域 ≤ 1 |
| **次按钮** secondary | surface 底 + border-strong 边 + text-1 | 与主任务并列的动作：导出、查询、取消 | ≤ 2，多的进“更多” |
| **文字按钮** ghost/text | 无底无边，text-2，悬停 surface-hover | 低频、可逆动作：重置、收起、行内操作 | 不限，但成组时 ≤ 3 |
| **危险按钮** danger | 次按钮外观 + danger 文字；二次确认弹窗里才用 danger 实心 | 删除、作废、批量取消 | 危险操作必须二次确认 |
| **图标按钮** | 无底，悬停 surface-hover，必须带 tooltip | 刷新、列设置、帮助 | — |

- **主按钮不用关注色，不用语义色。** 不出现“绿色提交”“橙色导出”。
- 禁用态：整体降为 text-disabled，不改变外形；能说明原因时加 tooltip。
- 加载态：按钮内文字前加加载图标，宽度不变，不可重复点击。
- 链接：主操作色文字 + 浅色下划线（border-strong），悬停下划线加深。

### 7.2 关注色可以出现的地方（白名单）

关注色是稀缺资源。**只允许**出现在：

1. 需要人工处理的 KPI 卡（边框 + “需关注”小标签）；
2. 侧栏/Tab 上“待处理”类计数徽标；
3. 页面内的提示条（callout）—— 提示“建议你做某事”，不是报错；
4. 新功能/新数据的一次性标记（看过即消失）。

**一屏合计 ≤ 2 处。** 以下位置**禁止**用关注色：按钮、链接、表格状态标签、图表系列色、选中态、焦点环。

### 7.3 状态标签

- 状态 → 语义角色的映射全产品统一，写成一张表，所有页面共用：

| 业务状态示例 | 角色 |
|---|---|
| 已完成、已支付、正常、已上线 | success |
| 待处理、待审核、即将到期 | warning |
| 失败、已取消（异常）、已超时 | danger |
| 进行中、配送中、处理中 | info |
| 草稿、已关闭、已归档 | neutral（中性灰） |

- 外观：**浅底 + 实色文字 + 可选圆点**，高度 caption 行高 + 4px，圆角 r-control。表格里**不用实心饱和色块**。
- 同一个状态在列表、详情、筛选项里颜色必须一致。
- 一种语义色最多对应 3–4 个业务状态；不够分时用文字区分，不加新颜色。
- 纯分类（渠道、门店类型、支付方式）**不是状态**，用中性描边标签或纯文本，不上色。

### 7.4 表单与校验

- label 用 text-2；必填星号用 danger；说明用 caption + text-3，放在控件下方。
- 焦点：border 变为 text-3 档 + 3px 主操作色 12% 透明度的焦点环。不用彩色粗边框。
- 校验失败：border 和说明文字变 danger；**只在失焦或提交后提示**，不在输入中途报错。
- 只读信息用描述列表（label 列定宽，text-3；值 text-1），不要用禁用输入框展示只读数据。

### 7.5 空、加载、错误

| 状态 | 规则 |
|---|---|
| **空 · 首次** | 一行说明“这里会显示什么” + 一个引导动作（次按钮，不是主按钮；页面头已有主按钮时不重复）。不放大插画，最多一个中性线性图标。 |
| **空 · 筛选无结果** | “没有符合条件的记录” + “清除筛选”文字按钮。保留表头和筛选栏。 |
| **加载 · 首次** | 骨架屏，形状与真实布局一致（表格就是表格骨架），中性 surface-hover 色。 |
| **加载 · 刷新** | 保留旧数据，顶部细进度条或区域内轻量加载图标；不清空、不整页遮罩。 |
| **加载 · 操作** | 按钮内加载态（§7.1）。 |
| **错误 · 局部** | 在出错区域内显示：一句人话原因 + “重试”文字按钮。不要整页报错。 |
| **错误 · 整页** | 只用于 403/404/500：标题（title 档）+ 一行说明 + 返回/重试。不用卡通插画。 |
| **反馈提示** | 成功用轻提示（2–3 秒自动消失）；失败的提示**不自动消失**，必须给出下一步。 |

### 7.6 其他通用规则

- **图标**：一套线性图标，16px（菜单、按钮）/ 14px（表头、辅助），描边 1.5–1.75，颜色跟随文字。不用彩色图标、不混用面性和线性。
- **图表**：默认中性灰阶 + 主操作色；多系列时用同一色相的明度梯度，最多 5 个系列；语义色只表达好坏。
- **焦点可见**：所有可交互元素必须有可见的键盘焦点样式（焦点环），不能因“好看”去掉 outline 而不补。
- **暗色模式**：如需支持，只重新取值角色层，规则层一字不改。

## 8. 落地清单：在不同 UI 库里执行

### 8.1 通用步骤（任何库都一样）

1. **角色对表**：按 §3.3 把库的 token 一一对到角色，填入取值（可直接用 §3.4 参考实现）。
2. **扩展关注色**：新增一个 `attention` 变量（实色 / soft / border），不覆盖任何库默认色。
3. **全局尺寸**：控件高 = C；圆角三级；正文 14px；行高对 4 取整。
4. **根节点开 tabular-nums**；覆盖库字体栈。
5. **关阴影**：卡片类组件阴影设为无，改用 1px border。
6. **写状态映射表**（§7.3）成为一个共享常量，所有状态标签从它取色。
7. **用 §9 验收清单**逐页检查。

### 8.2 Ant Design（v5）

| 做 | 不做 |
|---|---|
| 用 `ConfigProvider theme.token` 一次性改 `colorPrimary`、`colorInfo`、`colorText*`、`colorBorder*`、`colorBgLayout`、`borderRadius`、`controlHeight`、`fontSize` | 不在组件上逐个写 `style` 改色 |
| 单独设 `colorInfo`，避免跟随近黑主色 | 不保留默认 Ant 蓝作主色（除非它在你的取值里满足 §3.2） |
| `Table` 用 `components.Table` 设 `headerBg`、`rowHoverBg`、`cellPaddingInline` | 不开 `bordered` 竖线表格 |
| `Card` 设 `boxShadow: none`，用 `bordered` | 不用 `hoverable` 浮起效果 |
| `Tag` 用 `bordered={false}` + 语义色的 soft 档 | 不用 `color="#xxx"` 自定义饱和色块 |
| 按钮层级：`type="primary"` / `default` / `text` 对应主/次/文字 | 不用 `type="dashed"`、`type="link"` 做按钮组主角 |

### 8.3 Element Plus

| 做 | 不做 |
|---|---|
| 覆盖 `:root` 的 `--el-color-primary` 及其 `-light-3/5/7/8/9`、`-dark-2` 全套（必须一起生成，否则悬停色会错） | 只改 `--el-color-primary` 一个变量 |
| `--el-border-radius-base`、`--el-component-size` 按 §5 设置 | 混用 `size="large"` 和默认尺寸 |
| `el-table` 去掉 `border`、`stripe`；表头用 `header-cell-style` 或变量设 surface-subtle | 开斑马纹 |
| `el-tag` 用 `effect="light"`；中性状态用 `type="info"` | 用 `effect="dark"` 的实心标签放表格 |
| 卡片 `shadow="never"` | `shadow="hover"` / `always` |

### 8.4 shadcn/ui（Tailwind）

| 做 | 不做 |
|---|---|
| 在 `globals.css` 改 `--background`、`--card`、`--border`、`--input`、`--foreground`、`--muted-foreground`、`--primary`、`--ring`、`--radius` | 把 shadcn 默认主题当成“规范已完成” —— 它只是一种取值，规则层还需执行 |
| 新增 `--attention`、`--success`、`--warning`、`--info` 及其 soft 档，并在 Tailwind 配置里注册 | 用 shadcn 的 `--accent` 当关注色（它是悬停底） |
| `Button` 变体对应：`default` = 主，`outline` = 次，`ghost` = 文字，`destructive` 只在确认弹窗里 | 一个视图里出现多个 `default` 按钮 |
| `Table` 补上表头底色、行高（shadcn 默认偏松，按密度档改） | 沿用默认 `h-12` 行高而不对齐密度档 |
| `Badge` 用 soft 底 + 实色字的自定义变体做状态标签 | 用 `default`（实心黑）Badge 表示状态 |

### 8.5 MUI

| 做 | 不做 |
|---|---|
| `createTheme` 设 `palette`、`shape.borderRadius`、`typography.fontSize: 14`、`typography.fontWeightBold: 600` | 保留 Material 默认 elevation 阴影 |
| 全局 `components.MuiPaper.defaultProps.elevation = 0` + `variant="outlined"` | 用 `elevation={2}` 之类给卡片加深度 |
| `MuiButton` 默认 `disableElevation`，`size` 统一 | 用 `variant="contained" color="secondary"` 做第二个主按钮 |
| 扩展 `palette.attention` 并做 TypeScript 声明 | 用 `secondary` 色当关注色（MUI 的 secondary 会被很多组件默认使用） |

### 8.6 手写 CSS / 自研组件

| 做 | 不做 |
|---|---|
| 先写**角色变量**（`--role-canvas`、`--role-action`…），组件只引用角色变量 | 组件里直接写色值 |
| 参考 `reference-tokens.css` 的结构，替换取值 | 把参考文件当成必须原样使用的主题 |
| 密度用一个容器属性（如 `data-density`）整体切换 | 每个组件自己定义尺寸 |

## 9. 验收清单（任何页面、任何库）

逐条打勾，全部通过即合规：

- [ ] 页面上有颜色的地方，都能归入 action / attention / 语义色之一。

## 10. 明确不做的事（Non-goals）

- **不发布组件库。** 这里没有 Button、Table 的实现代码，也不打算有。组件请用你选的库。
- **不替代 shadcn、Ant Design、Element Plus、MUI。** 规范站在它们上面，只决定“怎么用”，不重造“用什么”。
- **不锁定色板。** §3.4 只是参考实现；产品可以有自己的取值，只要满足 §3.2。
- **不覆盖营销页、官网、移动端 App。** 它们有不同的阅读情境，需要另一份规范。
- **不规定业务交互流程**（审批流、权限模型等），只规定这些流程在界面上的视觉呈现。
